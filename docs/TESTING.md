## 本轮修复

- 前端业务数据从 localStorage 模拟迁移为服务端持久化。
- 协议和 UI 均使用明确的配置错误，缺少密钥不会虚假成功。
- 预览和发布版本分离；新版本/片段重建失败保留旧的已发布内容。
- 任务原子领取与上传唯一索引，补齐重复执行与并发上传的竞争情况。
- 查询的 Embedding、Rerank、LLM 使用统一 trace_id；对话汇总按唯一子调用汇总，缺失用量不当作零。
- 取消可打断等待中的改写/检索/流式生成；已知用量与部分回答仍持久化。
- 请求校验错误移除被拒绝的原始输入，避免回传超长 Key 等凭据。
- 时间输出携带 UTC 偏移，前端按浏览器时区显示。
- API 重启时收尾遗留的生成中对话，保留部分回答与已知用量，避免会话一直被占用。
- 首屏只返回文档元数据和片段计数，片段正文按分页请求加载。

## 尚未验证

- Docker 在本机未安装，因此没有执行本机容器构建、PostgreSQL/Celery/Qdrant 远端组合联调或备份恢复演练。镜像标签通过官方 Docker Hub 元数据确认存在，并提供了 CI Compose 冒烟步骤；GitHub Actions 的执行结果以仓库页面为准，本地自测通过不代表容器检查已经通过。
- 没有用户提供的服务商 Key / OCR AccessKey，未执行真实 API 费用调用。扫描 PDF、复杂表格、内嵌图片、旧 DOC 与 XLS 等代表性样本需在真实账号下追加验收。
- 未进行 1 万文件、20 路并发的容量压测；无延迟、准确率或成本的未经验证承诺。
- 浏览器未覆盖完整移动端/多浏览器矩阵，停止流式与来源引用的核心正确性由 API 端到端和专项测试验证，当前未用真实模型在 UI 中重复验收。
- 生产构建主 JS 包约 1.21 MB，gzip 约 387 KB，存在体积提示；页面拆包优化可后续处理。

## 真实服务验收建议

1. 每家服务商分别测试 LLM/Embedding/Rerank，并记录实际型号、地区、维度和 usage 返回方式。
2. 用电子/扫描/混合 PDF、表格和图片样本检查来源、字段缺失和识别错误；错误文件要确认能够重试或保留旧版本。
3. 用独立问题集评估事实、表格数字、资料外问题、多轮指代、冲突版本与引用有效性。
4. 在计划部署的服务器上执行 Compose 冒烟、重启恢复、备份恢复和逐级并发测试，再评估是否达到企业试用要求。
